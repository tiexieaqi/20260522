# Skill规则审计报告

> 审计范围：用户提供的 5 份历史 Skill 文件。本文档仅记录审计结果，不改写历史 Skill，也不执行规则库重构。

## 一、所有 Skill 来源列表

| 文件名称 | 核心用途 | 适用阶段 |
|---|---|---|
| 剧本创作 Skill v2.0（单文档完整版）(2).md | 收集项目信息、提取对标作品 DNA、生成大纲、组织多视角审稿、形成项目档案 | 创作前期、立项、总体开发 |
| 剧本写作 Skill v1.0（单文件多模态版）(2).md | 根据项目档案和大纲进行标准剧本或小说化剧本写作，管理节奏、分集和写作模式 | 大纲之后、剧本初稿与改写 |
| Skill 3：剧本医生 · 圆桌会诊（轮替版）(1).md | 召集不同立场的评委，对剧本进行结构、市场、类型和执行层面的会诊 | 初稿评估、修改决策、复审 |
| Skill 4：台词专家 · 全量诊断（自动切换版）(1).md | 逐句检查角色辨识度、潜台词、冲突推进、类型语感、信息效率、节奏和金句潜力 | 分场或全剧台词打磨 |
| 🎬 顶级真人剧 AI 资产库架构师总指令.md | 从剧本和分镜提取角色、群体、生物、场景、服装、道具、车辆等可复用真人剧资产，并建立 ID、变体和调用表 | 剧本/分镜之后，视觉开发与生成前 |

### 交叉接口

- 剧本创作 v2.0 产出项目档案和大纲，剧本写作 v1.0 将其作为前置输入。
- 剧本医生可选用项目档案和 DNA 报告；没有这些资料时仍可独立会诊。
- 台词专家只处理台词层面，结构和剧情问题回指剧本医生。
- 资产架构师读取剧本、分镜、人物小传和场景描述，使用资产 ID 服务后续分镜与视频生成。

## 二、规则分类

### 1. 总导演原则

来源：剧本创作 v2.0、剧本写作 v1.0、剧本医生、台词专家、资产架构师。

共同原则包括：先完成自检和信息收集；不凭空捏造关键设定；发现档案、大纲或用户指令冲突时先停下确认；保持真实反馈，禁止无依据的捧杀；所有后续输出服从项目的统一视觉和叙事约束。

### 2. 剧本分析

来源：剧本创作 v2.0、剧本医生、剧本写作 v1.0。

包括故事梗概和三幕/分集结构、核心冲突、主题、节奏、场景节点、项目 DNA、多视角审稿，以及按证据引用原文的诊断要求。

### 3. 资产生成

来源：资产库架构师。

包括零遗漏扫描、资产分类、资产总表、资产变体表、固定锚点、原文依据、待确认项、真人剧实拍质感和统一视觉圣经。

### 4. 人物连续性

来源：资产库架构师、剧本创作 v2.0、剧本写作 v1.0、台词专家。

包括人物外貌、体型、发型、服装、妆造、身份气质、性格与关系连续性；变更需拆分变体并记录场次；项目档案中的人物设定优先于临时推断。

### 5. 场景设计

来源：资产库架构师、剧本写作 v1.0、剧本创作 v2.0。

包括场景头、地点与时间、空间结构、出入口、家具和关键道具、光线与氛围、方位拆分、时间/天气/破坏状态变体。资产架构师规定场景资产使用 2:1 全景信息图，具体剧情镜头默认 16:9。

### 6. 道具设计

来源：资产库架构师。

包括道具和武器的提取、真实材质与重量、功能、状态变体、唯一 ID、出现场次、剧情作用和道具调用表。道具资产统一按 16:9 处理。

### 7. 分镜设计

来源：资产库架构师、剧本写作 v1.0、剧本创作 v2.0。

包括镜头号、场次、景别、运镜、光线、情绪、镜头提示词、资产 ID 调用和镜头连续性。历史 Skill 没有形成独立的焦段、时长或完整分镜模板规范。

### 8. 视频模型适配

来源：资产库架构师的“视频模型 @Image 锚点”和镜头调用提示词要求，以及剧本写作中面向 AI 生成的流程描述。

未发现专门的 Seedance 2.0、Seedance 2.5、即梦 2.0 或即梦 2.5 规则章节，也未发现四个模型之间可直接比较的参数约束。因此该类别目前只有通用资产调用原则，不能据此判定模型间存在冲突。

### 9. 历史真实性审核

来源：台词专家、剧本创作 v2.0、剧本写作 v1.0。

包括年代背景、语言和称谓、术语、物件、社会习俗、身份和历史设定的匹配；不明信息标记待确认。历史 Skill 没有独立的审核清单或问题分级制度。

## 三、规则冲突检测

### 1. 即梦 2.0 与即梦 2.5

未发现直接规则。5 份历史 Skill 没有分别定义即梦 2.0 或即梦 2.5 的提示词格式、画幅、时长、运镜或 Seed 行为，因此当前不存在可比对的版本冲突。后续新增模型规则时应明确版本边界，避免把通用规则误写成单一版本规则。

### 2. Seedance 与即梦

未发现直接规则。历史文件只要求资产能够作为视频模型的 `@Image` 锚点，并规定镜头提示词调用资产 ID；没有 Seedance 与即梦的专属语法或参数，因而不能认定二者冲突。后续模型适配规则应以通用资产和分镜约束为上游来源。

### 3. 不同 Skill 的重复规则

发现以下重复或高度重叠：

- “开场先自检、复述已理解内容、再开始工作”同时出现在剧本创作、剧本写作、剧本医生和台词专家中。
- “真实反馈、禁止捧杀、必须给证据”同时出现在剧本创作、剧本医生和台词专家中。
- “信息不足先追问、不假装理解、不凭空捏造”同时出现在多个 Skill 的前置和异常处理章节。
- “项目档案、大纲、DNA 报告是下游输入”在剧本创作、剧本写作和剧本医生之间重复描述。
- 场景、镜头、台词、人物连续性和资产引用在写作 Skill 与资产架构师中有接口重叠，但细化程度不同。

建议重构时将这些内容提升为总导演规则或通用制作规则，由各 Skill 只保留专属执行部分。

### 4. 临时项目规则混入通用规则

发现存在应隔离的项目级内容：

- 对标作品 DNA 报告及其具体规律，只适用于当前项目或当前会话。
- 项目档案中的角色名、地名、招式、历史背景、性格三层和已写场景。
- 各 Skill 的示例项目、示例角色、示例台词、示例场景和类型评委组合。
- 资产架构师要求建立的“本项目视觉圣经”、项目专属风格、颜色、光影和资产状态。

这些内容不应直接写入通用规则文件，应放入项目档案、DNA 报告或项目资产资料，并以“待确认/本项目专用”标注。

## 四、规则优先级设计

### 最高优先级：总导演规则

负责统一目标、输入确认、事实边界、冲突停问、禁止捏造、项目约束继承和最终输出方向。任何下游 Skill 与其冲突时，先暂停并请求确认。

### 第二级：通用制作规则

包括剧本分析、资产生成、人物连续性、场景设计、道具设计、分镜设计和历史真实性审核。这些规则适用于所有项目和模型，并应保持跨工具一致。

### 第三级：模型适配规则

包括 Seedance 2.0、Seedance 2.5、即梦 2.0、即梦 2.5 等平台或版本的提示词格式、参数表达和输入限制。模型规则只能在不破坏上两级约束的前提下调整表达方式。

### 第四级：具体项目规则

包括项目档案、DNA 报告、视觉圣经、角色卡、场景卡、资产变体、临时指令和用户确认的本项目例外。其作用域仅限指定项目或会话；与上级规则冲突时必须标记并确认，不能静默覆盖。

### 建议的冲突处理顺序

1. 先检查是否违反总导演规则。
2. 再检查是否违反通用制作规则。
3. 再检查模型版本是否有专属限制。
4. 最后应用项目级设定和已确认的临时例外。
5. 无法判定时保留冲突双方，标记“待确认”，不自行选择。

## 审计结论

历史 Skill 的主要问题不是模型规则互相冲突，而是通用原则在多个文件中重复、项目资料与通用规则边界不够清晰，以及视频模型和历史真实性缺少独立规范。后续重构应先抽取总导演原则和通用制作规则，再把模型适配与项目资料分层接入。本报告完成后，方可进入规则库重构阶段。
